## 可靠性测试覆盖

- 平台图无环、变量、分支真假选择、汇合与结构化 JSON 字段判断。
- 多线程相同幂等键创建同一 run，不同输入复用键返回 409。
- 编辑草稿和配置不会改变已创建任务的版本与配置。
- 独立进程执行到人审暂停，退出后由新进程从 PostgresSaver 检查点继续。
- 子进程在节点结果提交后立即退出，恢复时完成事件不重复。
- SKIP LOCKED 独占领取，活跃图调用的 advisory lock 阻止租约误接管。
- 重复审批冲突、拒绝终态、排队/执行中/暂停取消、失联取消需人工检查。
- SSE Last-Event-ID 和 after 游标补拉；前端去重、重试文本分代、切换任务时旧事件隔离。
- 工具只读瞬时重试与永久错误边界；计算器拒绝代码、幂和文件访问。
- 模型与工具预算跨重试累积；失败前实际返回的 usage 保留，未知请求明确标记。
- 上传原字节、文件名、分块关联、来源、扫描 PDF 限制与索引模式隔离。
- 安装的 OpenAI SDK 使用注入 HTTP transport 验证真实 SSE、usage、Embedding dimensions 与工具消息协议。
- 未配置真实模型时失败并保存 node.failed，不降级到演示输出。

## 完整服务重启验收

另做了一次开发环境的端到端验收，与 pytest 子进程测试分开：

1. 通过 HTTP 创建预置“需求评审”，实际查询 pgvector 并执行知识工具。
2. 等待 paused，确认审批记录和检查点已经落盘。
3. **同时停止 API 和 worker**，再启动全新进程。
4. 读取同一 runId，状态仍为 paused；修改报告后确认。
5. 同一任务完成，工具调用数重启前后都为 1。
6. 重复审批返回 409；最终引用关联 example-doc-0-0。
7. 通过 Last-Event-ID 补拉 23 个剩余事件，序列与事件表完全一致；Markdown 下载正确。
