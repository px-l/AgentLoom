# 画布性能测量

## 可重复场景

启动开发服务后运行 `pnpm perf`，需要本机 Chrome。脚本位于 `apps/web/tests/canvas.perf.ts`，访问 `/benchmark?nodes=100` 等页面，复用正式编辑器的 Canvas、memo 节点、连线与 Zustand 状态实现，不访问数据库。

每种 100/300/500 节点场景有 n-1 条链式连线，所有节点实际挂载，节点分布在 10 列网格。等待两帧后记录初始化区间，再等待 300ms 稳定，使用真实鼠标事件拖拽第一个节点：60 次 pointer move，每次等待约 12ms，横向总位移 177px，纵向正弦变化。拖拽过程中 requestAnimationFrame 采样帧间隔，PerformanceObserver 记录超过 50ms 的 long task。每种节点数重复三次。

同时断言：一次拖拽只形成 **1 个历史记录、1 个保存信号**。基准不写数据库；正式编辑器在信号后约 900ms 自动保存。

## 本次实测

时间：2026-10-26 18:52（Asia/Shanghai）。Apple M5、arm64、10 逻辑核、16 GiB，macOS、Chrome Headless 155，1440×1000 视口，Vite 开发模式。原始数据：[performance-results.json](performance-results.json)。

| 节点 / 连线 | 初始化区间中位数 ms | 各次拖拽 p95 范围 ms | 最大观测帧间隔 ms | 拖拽 long task |
|---|---:|---:|---:|---:|
| 100 / 99 | 100.0 | 16.7–16.8 | 16.8 | 0 |
| 300 / 299 | 154.9 | 16.7–16.7 | 16.8 | 0 |
| 500 / 499 | 203.6 | 16.8–16.8 | 33.4 | 0 |

初始化时间仅为加载 Zustand 图数据到两次 RAF 的区间，不是完整冷启动、所有浏览器绘制完成或真实交互延迟。p95 描述这一脚本的帧采样，并不等价于产品在所有设备上的保证。

没有优化前的同条件基线，因此没有“提升百分比”。如果要比较优化，保存当前 JSON 后，在同一设备、浏览器、构建模式、节点数、视口和脚本下修改实现再运行，比较两组原始样本。

## 已落实的实现选择

- 自定义节点 memo，nodeTypes、连线选项、事件处理函数稳定。
- 修改单个节点保持其余节点对象引用；属性面板按选中节点订阅。
- 每个节点只订阅自身 run 状态，避免整幅图随文本增量刷新。
- applyNodeChanges 更新拖动位置，拖拽开始记录一次撤销快照，结束才标记待保存。
- 属性、节点/连线变更走独立编辑动作；保存有延迟与草稿乐观锁。
- SSE 文本以 70ms 批次合并，画布不订阅全量文本。

## 测量限制

样本只有每组 3 次，使用固定节点形态与单节点拖拽。没有高密度交叉边、超长属性、多选移动、多个同时流式运行、低配设备、后台标签页或真实用户输入延迟测量。headless、开发模式和自动化等待也会影响结果。该数据仅作为可重复回归起点，不是通用性能承诺。
